# 红果短剧 CapyPlayer 组件 · 技术报告

> 日期：2026-10-01　|　结论：**可行，已交付并实测通过（36/36 断言）**

---

## 一、一句话结论

红果短剧**网页版**（`hongguoduanju.com`）的 SSR 页面里带完整数据（`window._ROUTER_DATA`），
**免签名、免 Cookie、免登录**，且播放页返回的是**明文 MP4 直链**。因此 CapyPlayer 组件可以做到
**零后端、零依赖**。

唯一硬限制：**每部剧只开放前 3 集试看**，第 4 集起播放页返回 404。

---

## 二、两条链路的可行性对比（实测）

红果有两条独立数据链路，能力差异很大：

| 维度 | 网页版 `hongguoduanju.com` | App 接口 `api5-normal-sinfonlineb.fqnovel.com` |
|---|---|---|
| 鉴权 | **无需**签名 / Cookie / 登录 | **需要** `X-Gorgon` + `X-SS-STUB` + 一堆设备参数 |
| 签名难度 | — | **纯算法可离线复现**（本项目已用 Python 验证通过 ✅） |
| 列表分页 | `?page=N`，24 条/页 | `offset` + `session_id` 游标，18 条/页 |
| 搜索 | ✅ 有（路径式 `/search/<kw>`） | 有（需签名） |
| 详情 | ✅ 返回**完整** `vid_list`（77/1000 集都有） | 同左 |
| **播放地址** | ✅ **明文 MP4**（HTTP 206 + `ftyp/isom`） | ❌ **CENC AES-128-CTR 加密**，密钥需从 `spade_a` 推导 |
| 可播集数 | **仅前 3 集**（`accessible_episode_cnt`） | 全量，但需自建解密代理 |
| 请求头依赖 | 不校验 Referer / UA（伪造第三方 Referer 才 403） | 强校验 UA |
| 视频编码 | 明文 MP4 | 1080p=`bytevc1`(HEVC)，720p 及以下=`bytevc2`(字节自研) |

### 实测原始数据

**列表** `GET /category/real-drama`

```
HTTP 200 · 24 条 · pagination {"total":800,"pageNum":1,"pageSize":24,"totalPages":34}
首条: {"series_id":"7687919221593885758","series_name":"二嫁有喜",
       "episode_cnt":77,"accessible_episode_cnt":3,"episode_right_text":"全77集"}
```

**取流** `GET /player/7687919221593885758/7687921187195735102`

```
HTTP 206 · Content-Type: video/mp4
首 32 字节: 00000020 66747970 69736f6d ...   → "ftyp" + "isom" = 标准未加密 MP4
```

**Referer 依赖性**（同一个直链，5 种请求头组合）

| 请求头 | 结果 |
|---|---|
| 不带任何 Referer | ✅ 206 |
| `Referer: hongguoduanju.com/` | ✅ 206 |
| `Referer: novel.snssdk.com/` | ✅ 206 |
| `Referer: evil.example.com/`（伪造第三方） | ❌ 403 |
| 无 UA 无 Referer | ✅ 206 |

> 结论：把裸 URL 交给播放器即可，**不需要 customHeaders**。

**试看限制**（跨 3 个频道抽 18 部剧）

```

二嫁有喜(总77集): 第1集 ✓ / 第3集 ✓ / 第4集 404 / 第77集 404
```

## 三、接口协议（组件实现依据）

所有数据都在 SSR 页面的 `window._ROUTER_DATA.loaderData` 里，需做**跳过字符串字面量的括号配对**提取
（不能用正则，JSON 是嵌套结构）。

| 用途 | 请求 | 取数路径 |
|---|---|---|
| 分类列表 | `GET /category/{route}`<br>`GET /category/{route}?page=N`（N≥2） | `loaderData["category_$"].recommendList[]`<br>`.pagination` |
| 搜索 | `GET /search/{keyword}` | `loaderData["search_(keyword)/page"].searchList[]`<br>`.totalCount` |
| 详情 | `GET /detail?series_id={id}` | `loaderData["detail_page"].seriesDetail`<br>→ `vid_list[]` `celebrities[]` `tags[]` `accessible_episode_cnt` |
| 取流 | `GET /player/{series_id}/{vid}` | `loaderData["player_(series_id)/(vid)/page"]`<br>→ `video_player_info.main_url` |

`{route}` 取值：`real-drama`(真人剧) `comic-drama`(漫剧) `ai-drama`(AI剧) `comic`(动漫)

> ⚠️ 两个坑：
> 1. `page=1` 会被站点 **301** 到无参规范地址 → 组件对 page=1 不带查询参数。
> 2. 取流页的 loaderData 层名带**动态片段**（`player_(series_id)/(vid)/page`），不能按固定名取，
>    组件改为**扫描所有层找含 `video_player_info` 的那个**。

## 五、风险与限制

### P0 · 必须让用户知道

| # | 问题 | 影响 | 处置 |
|---|---|---|---|
| P0-1 | **每剧仅前 3 集可播** | 用户点进 77 集的剧只能看 3 集 | 组件默认只输出可播集，并在 `description` 末尾标注「可播 3 集 / 全 77 集」；要全集需接解密代理 |
| P0-2 | **直链是时效签名** | URL 里带 `l=<时间戳>`，过期后 403 | 组件每次都**实时解析**，不做跨会话缓存（`cacheDuration` 已设为 10 分钟） |
| P0-3 | **耦合第三方站点结构** | 红果改版 → 组件失效 | 所有解析集中在一层，失效时只需改 `hgExtractRouterData` 的层名常量；`isSuccess` 字段已在监控 |

### P1 · 需要留意

| # | 问题 | 说明 |
|---|---|---|
| P1-1 | **单次响应体较大** | 列表页 ~250KB、详情页 ~450KB。若 CapyPlayer 沙箱有响应体上限，可能被截断。组件已做「解析失败即返回空数组 + 打日志」的降级 |
| P1-2 | **列表页无筛选参数** | 站点有 `selectorList`（主题/设定/背景/受众/排序）维度，但筛选 URL 形式未验证，本版未接入 |
| P1-3 | **推荐位不稳定** | `detail_page.recommendations` 实测两部剧均为空数组，组件已做「有则用、无则忽略」 |
| P1-4 | **演员表并非每部都有** | `celebrities` 部分剧为空，组件已过滤空 `name` |

### P2 · 可选优化

- 接入 `selectorList` 筛选维度，做成更多分类入口
- 用 App 签名接口（已验证可复现）补齐搜索结果数量与全集元数据
- 加入请求结果本地缓存，减少重复拉取

## 七、升级路径：如何解锁「全集」

红果 App 接口下发的视频是 `CENC AES-128-CTR` 加密的，播放器无法解码，所以必须有一层服务端做解密。
组件已预留接口，改一个常量即可切换：

```js
// widget/hongguo.js
var HG_CONFIG = {
  // 置空 = 纯网页版（前 3 集）
  // 填入你的服务地址 = 全集可播
  proxyBase: "https://your-host/hg",
};
```

填好后，每集播放地址会变成：

```
{proxyBase}/stream?series_id=<剧ID>&ep=<集号>
```

代理服务的实现要点（依据 `_inspect` 里的源码）：

1. 用 **X-Gorgon 纯算法签名**（`provider_hongguo_sign.go:23-47`，已实测可离线复现）调
   `/novel/player/video_model/v1/` 拿 `main_url` + `encrypt_info.spade_a`
2. 用 `hongguoContentKey()` 的算法（`provider_hongguo_playback.go:159-201`）把 `spade_a` 推出 16 字节 AES-128 密钥
3. 拉取 CDN 密文 mp4，读 `senc` 盒里的 `base_iv`，按 `AES-128-CTR` 逐样本解密
4. 以支持 **HTTP Range** 的方式串流明文 mp4（拖动进度条必需）
5. 注意：720p 及以下是 `bytevc2` 编码，**必须固定选 1080p（HEVC）**，否则播放器解不了
