# CapyPlayer 组件：能做什么 & 哪些资源能用

> 2026-10-01　全部结论均基于实测，非文档推测。

---

## 一、组件能做什么（能力边界）

CapyPlayer 的组件本质是**「数据源适配器」**，不是 UI 层。你能控制的是**内容**，不是**界面**。

### ✅ 能做的

| 能力 | 实现方式 | 说明 |
|---|---|---|
| **内容列表** | `modules[].type = "media_list"`<br>返回 `MediaItem[]` | 海报墙。每条含标题/封面/简介/评分/年份/标签 |
| **分类导航** | `type = "category"`<br>返回 `WidgetSystemCategory[]` | 每个分类可携带 `params`，点击后透传给列表模块 |
| **搜索** | 普通 `media_list` + `string` 类型参数 | 关键词检索 |
| **分页** | `params: [{type:"page"}]` | 系统注入页码，从 1 开始 |
| **详情二次解析** | 全局 `loadDetail(link)` | 条目带 `link` 时进入，可返回剧集结构 |
| **多季多集** | `seasons[] / episodes[]` | 短剧用「单季 N 集」即可 |
| **多播放线路** | `playSources[]` | 同一集多线路切换（线路一/线路二） |
| **演职员表** | `credits.cast[]` | 需非空 `name`；`source:"tmdb"` 才进 TMDB 人物页 |
| **推荐位 / 相关视频** | `recommendations[] / relatedVideos[]` | 各最多 30 条；相关视频可带 `customHeaders` |
| **直接播放** | `{type:"url", videoUrl}` | 给个直链就播，不需要 `loadDetail` |
| **跨请求持久化** | `Widget.storage` | 存 token / cookie / 游标 |
| **TMDB 数据** | `Widget.tmdb.get()` | 内置封装，自动处理 base URL |
| **HTML 解析** | `Widget.dom.parse/select/text/attr` | 抓网页型站点用 |
| **多源回退** | 组件内部逻辑 | 一个组件里可以自己实现「A 源挂了走 B 源」 |

### ❌ 不能做的（别浪费时间）

| 限制 | 原因 |
|---|---|
| **自定义 UI / 布局** | 组件只能**填充现有详情页的既有区块**（标签、演职员、推荐、相关视频）。不能加自己的按钮、Tab、样式、可执行 UI |
| **后台任务 / 定时 / 轮询** | 无定时器持久化，函数调用完沙箱就结束 |
| **WebSocket / 长连接** | 沙箱不提供 |
| **解密加密视频流** | 拿不到字节流，无法做 AES/DRM 解密（这是红果全集限制的根因） |
| **绕过 DRM** | 同上 |
| **跨请求内存缓存** | 除 `Widget.storage` 外无共享状态 |
| **依赖未文档化字段驱动逻辑** | 官方明令禁止，且版本升级会失效 |

### 关键设计约束

> **`type`（条目行为）≠ `mediaType`（内容类型）**
> - `type` 决定「点进去干什么」：`link` → 走 `loadDetail`；`url` → 直接播
> - `mediaType` 只描述「这是电影还是剧集」
>
> **`videoUrl` 优先级高于 `link`。** 同一集既有直链又有详情页时，直链赢。

## 二、哪些资源可以用来做组件

按「接入成本」从低到高分五层。**层级越低，性价比越高。**

### Layer 0 · 内置资源（零成本）

| 资源 | 接法 |
|---|---|
| **TMDB** | 直接用 `Widget.tmdb.get()`，做发现页 / 海报墙 / 分类榜单最快 |
| **任意 m3u8 / mp4 直链** | 返回 `{type:"url", videoUrl}` 即可，连 `loadDetail` 都不用写 |
| **Emby / Jellyfin** | App 本身支持，组件也能封装第三方服务器 |

> 💡 **做「发现页 / 榜单墙」类组件，TMDB 是最省事的起点** —— 零抓取、零风险、零维护。

### Layer 1 · 免签名 SSR 站点（★ 推荐起点）

站点是服务端渲染的，数据直接嵌在 HTML 里（`__INITIAL_STATE__` / `_ROUTER_DATA` / `__NEXT_DATA__`），
**不需要签名、Cookie、登录**。

**已验证样本：红果短剧 `hongguoduanju.com`**

| 项 | 结果 |
|---|---|
| 分类 / 搜索 / 详情 | ✅ 全部免签名可拿 |
| 播放地址 | ✅ 明文 MP4，HTTP 206 + `video/mp4` + `ftyp` |
| Referer 校验 | ✅ 不校验（不带也 206） |
| ⚠️ 限制 | **每剧只开放前 3 集**，第 4 集起 404 |

### Layer 2 · 苹果CMS 站群（★★ 最大杠杆）

**苹果CMS（maccms）是国内最流行的开源影视建站程序，全网有上万个站点。**
它们的**路由和播放变量是统一的**，所以**一套解析代码能覆盖海量站点**。

**通用特征（实测命中）**

```js
// 播放页里一定有这个变量，url 字段就是播放地址
player_aaaa = {"flag":"play","encrypt":0,"trysee":0,"points":0,
               "link":"/index.php/vod/play/id/9500/sid/1/nid/1.html",
               "vod_data":{"vod_name":"绝世天医",...},
               "url":"https://.../index.m3u8"}
```

**统一路由**

| 用途 | 路径 |
|---|---|
| 分类列表 | `/index.php/vod/show/id/{分类ID}/page/{页码}.html` |
| 详情 | `/index.php/vod/detail/id/{剧ID}.html` |
| 播放 | `/index.php/vod/play/id/{剧ID}/sid/{线路}/nid/{集号}.html` |

**实测样本：五五短剧 `duanju55.com`** ← **比红果更好用**

| 项 | 结果 |
|---|---|
| 苹果CMS 标记 | ✅ 确认 |
| 播放变量 `player_aaaa` | ✅ 命中 |
| `encrypt` | **0 = 未加密** |
| `trysee` | **0 = 无试看限制** |
| 播放格式 | 明文 **m3u8**（HLS 点播） |
| 实际内容 | **2469 个分片 × 2 秒 = 82.3 分钟**，`PLAYLIST-TYPE:VOD`，**无 `#EXT-X-KEY`** |
| 对比红果 | 红果只能看前 3 集；这里是**整剧打包** |

> ⚠️ 注意：苹果CMS 的**采集 API** `/api.php/provide/vod/?ac=list` 常被站长关闭
> （实测 `xzyx168.com`、`duanju55.com` 均返回 `closed`）→ **必须走 HTML 解析**，不能指望 API。

## 四、推荐优先级

| 优先级 | 做什么 | 理由 |
|---|---|---|
| **P0** | **苹果CMS 通用适配器** | 一套代码覆盖上万个站点。实测五五短剧**整剧明文 m3u8、无试看限制**，体验远超红果 |
| **P1** | 红果（已完成） | 免签名、数据干净，但**只能看前 3 集** —— 适合做「发现/试看」场景 |
| **P2** | 多源聚合组件 | 用 Layer 2/3 做内部回退：A 站挂了自动走 B 站。**这是最有价值的形态** |
| **P3** | 接 52api.cn | 想省事就付费，但建议只作为兜底 |
| **P4** | 逆向 Layer 3 私有 API | 成本高、寿命短，**除非某个源内容独有，否则不值得** |

### 为什么不建议先做 Layer 3

- 每个源一套签名/加密，**一个源一份工作量**
- 寿命短（App 一升级就失效）
- 而 **Layer 2 的苹果CMS 是「一处适配，处处可用」**
- 红果那种 CENC 加密源，**还得自建解密代理**才能全集 —— 投入产出比最低

## 五、苹果CMS 通用解析法（可直接复用）

```js
// 1) 列表：/index.php/vod/show/id/{分类}/page/{页}.html
//    用 Widget.dom 抽 <a href="/index.php/vod/detail/id/NNN.html"> 与封面/标题

// 2) 详情：/index.php/vod/detail/id/{id}.html
//    抽 pcDrama_catalogItem / content__playlist / playlink 里的分集链接

// 3) 播放：/index.php/vod/play/id/{id}/sid/{s}/nid/{n}.html
//    抠出 player_aaaa，直接 JSON.parse

var PLAYER_RE = /player_aaaa\s*=\s*(\{.*?\})\s*<\/script>/s;

async function resolveMaccms(playUrl) {
  var html = (await Widget.http.get(playUrl, {
    headers: { Referer: playUrl }
  })).data;

  var m = PLAYER_RE.exec(html);
  if (!m) throw new Error("未找到 player_aaaa，可能不是苹果CMS 站");

  var info = JSON.parse(m[1]);
  if (Number(info.encrypt) !== 0) {
    throw new Error("该集已加密（encrypt=" + info.encrypt + "），需要额外解密");
  }
  if (!info.url) throw new Error("该集无播放地址");

  return info.url;   // 通常是明文 m3u8
}
```

**要点**

1. `encrypt: 0` 才算明文；非 0 需要额外处理
2. `trysee` 非 0 = 有试看限制
3. 有些站把**整剧打包成一个文件**（分集列表里只有「全集」），此时不用做选集
4. 采集 API（`/api.php/provide/vod/`）大概率被关，**直接走 HTML**
5. 各站的分类 ID、详情路由可能有差异 → 把「路由规则」做成配置表，别写死

## 六、合规提示

- 组件只做**数据搬运**，不存储、不分发视频文件
- 上述站点内容版权归各自平台所有
- **仅接入有授权或公开可访问的内容**，在符合当地法律法规的前提下使用
- CapyPlayer 官方文档亦声明：*内容合规由使用者自行负责*
